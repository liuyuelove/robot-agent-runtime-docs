    最容易混的十二组

    先把这些分清，后面五组表就不用逐条背了。

    这一对差别在哪
    转移矩阵 vs 转发矩阵前者 15 × 15，管状态与状态：能不能转过去。后者 15 × 18，管事件与状态：这个事实要不要被听见。两张表都叫「矩阵」，但回答的是完全不同的问题。
    Adapter vs ToolTool 是模型能调用的动作，Adapter 是动作最终落到的地方。Tool 不该知道协议，Adapter 不该知道模型。
    Adapter vs EngineEngine 是 Adapter 的第三种，但它连的不是外部世界，而是进程内的技术状态。判据是「管的是业务规则还是技术资源」——业务状态机不许进 Engine。
    Event vs Command事件是「已经发生了」，命令是「请去做」。总线只收前者。混进命令的代价是发布者会开始等结果。
    Event vs Snapshot事件是流：发生过什么。快照是点：现在是什么。没有快照，异步系统就没有「确认」这个动作。
    压缩 vs 截断压缩是保结构地重建，截断是直接丢。丢掉的如果是「办过 / 办成了」这类事实，模型就会把尝试说成完成。
    暂停 vs 取消（看门狗）暂停不是「把倒计时按住」，而是取消 timer；恢复不是「继续走」，而是重装完整时长。所以没有剩余时间，也不需要保存进度。
    Session vs Turn会话是容器，轮次是单位。一个人可以在一段会话里说十轮；换个人则要换会话。
    移动态 vs 驻停态十四种业务状态按「在动 / 不动」各分一份，加上急停共十五种。移动态默认屏蔽输入、只放行输出——但 WELCOMING_MOVING 放行前三种输入，PATROLLING_MOVING 与 GREETING_MOVING 放行人脸输入。别按注释推，按矩阵读。
    「办过」vs「办成了」动作发生过 ≠ 结果已确认。这两类事实分开存，压缩时不许合并，因为它们对模型的意义完全不同。
    公共合同 vs 实现细节合同是 Event / Snapshot / Config / 签名，实现是 transport、重连策略、内部异常。一旦把实现写进快照（比如 use_mock），实现就升格成合同，从此换不掉。
    fail-closed vs 降级降级是「还能提供一部分能力就继续」，fail-closed 是「拿不准就别动」。涉及运动与安全时用后者，涉及说话时用前者。

    A · 架构骨架

    术语定义与边界详见
    九层分层
    Layer    		app / agent / domain / tools / adapters / config / prompts / observability / shared。每层用「不许做什么」定义，不按技术栈切。≠ 目录分类：分层的判据是依赖方向，不是文件夹名字。03
    composition root
    组合根    		进程启动时唯一一处构造配置、创建 Adapter、装配运行时的代码。≠ 依赖注入容器：它不解析依赖图，只按固定顺序 new，然后绑定。01
    Adapter
    适配器    		进程与外部世界之间唯一的边界层。所有设备、外部服务、SDK 只能从这里进。≠ Tool：Tool 是模型能调用的动作，Adapter 是动作最终落到的地方。04
    Public Adapter
    公共适配器    		对外暴露稳定合同的 Adapter。系统共 27 个，上层只能通过 facade 拿到它，不能自己 new。04
    Hardware Adapter
    硬件适配器    		连物理设备或厂商硬件 SDK。必须同时提供 real.py 与 mock.py，否则测试只能连真机。04
    Integration Adapter
    集成适配器    		连进程外的软件服务或第三方平台。同样强制 Real + Mock 双实现。04
    Engine
    引擎    		只在进程内运行、但有状态和生命周期要管理的技术组件。是 Adapter 的第三种，准入门槛比前两类高。≠ 业务状态机：业务规则属于 domain，不许因为「它在进程内」就包装成 Engine。04
    Real / Mock 合同一致同一个 Adapter 的两种实现必须导出同一组 Event、Snapshot 与错误分类。测试里用 Mock 跑通的链路，换 Real 不能因为字段不一样就崩。04
    Adapter Runtime唯一管理 Adapter 实例与生命周期的组件：绑定 facade → 按稳定顺序 start() → 任一失败反向回滚并解绑。04
    公共 facade
    门面    		运行期解析 Adapter 实例的唯一入口，形如 from src.adapters import adapters。关键区别：import 可以，解析实例只能在受控时机——import 时 Runtime 可能还没绑定。04
    Tool
    工具    		模型可调用的一个能力，签名固定为 execute(input) -> output，不区分只读与副作用。≠ Adapter：Tool 不碰协议，只做参数校验与编排。05
    ToolRegistration一个 Tool 的唯一声明处。给模型看的 Schema、能力描述、可调用入口、启动期校验全部从它推导。05
    CapabilitySpec
    能力规格    		从 ToolRegistration 自动推导出的能力描述，给编排层与 prompt 装配使用。不许手写。05
    能力准入
    Engine 六项门槛    		判断一个进程内组件该不该包装成 Engine 的六条标准，满足至少三项才准。作用不是提高标准，是给「不要包装」一个可以引用的依据。04

    B · 事件与状态

    术语定义与边界详见
    Event Bus
    事件总线    		进程内的事实广播。只投递，不做路由决策，不保证顺序与幂等。06
    事实
    Fact    		已经发生、不可撤销的事。这是总线上唯一合法的语义。≠ 命令：命令是「请做某事」，不许上总线。06
    命令
    Command    		「请做某事」的请求。明确禁止进事件总线——一旦允许，就会出现「发出去还在等结果」的隐式 RPC，超时、重试、顺序全部变成未定义行为。06
    Subscriber
    订阅者    		接收事实的一方。不要求先于 Adapter 启动，除非模块声明了「无法由 Snapshot 恢复」的关键启动事实。06
    FrozenJsonValue公共事件里 JSON-like 字段的统一类型：递归不可变、可安全序列化。冻结与还原全项目只有一份实现（freeze_json() / thaw_json()），不许自己写递归。06
    Snapshot
    快照    		统一形态 snapshot() -> XxxSnapshot，回答「这个模块现在是什么状态」。≠ Event：事件说发生过什么，快照说现在是什么。没有快照，异步系统就没有确认手段。04
    Brain Input
    输入总线    		校验、去重、补 session_id，然后发布「输入已被接受」。不跑 Agent、不排队、不持久化。01
    Brain Output
    输出总线    		校验输出、维护局部输出生命周期、发布输出事实。不生成内容、不保证前端送达。01
    RobotState
    机器人状态机    		15 个状态，回答三件事：此刻能听见什么、能转到哪、转过去要做什么。08
    转移矩阵
    transition_matrix    		15 × 15。行是当前状态、列是目标状态，回答「能不能转过去」。对角线为 1，表示允许幂等切换。08
    转发矩阵
    forwarding_matrix    		15 × 18。行是当前状态、列是源事件，回答「这个状态下这个事实要不要被听见」。≠ 转移矩阵：一个管状态之间，一个管事件与状态之间。两张表最容易混。08
    Reaction
    反应    		状态转移后必须执行的动作，按模块分成 8 组。≠ 副作用：它是显式登记的，不是顺带发生的。08
    revision
    版本号    		状态机的单调递增版本号。reaction 入队时带上 revision，执行前发现已过期就丢弃，避免用旧状态做新决定。08
    幂等切换请求转移到「当前所在的状态」本身也允许，不报错、不触发额外动作。矩阵对角线为 1 就是为了这个。08

    C · 会话与上下文

    术语定义与边界详见
    Session
    会话    		一次连续交互的容器，承载历史、业务卡、已确认事实与当前状态。同一时刻只允许一个活跃会话。07
    Turn
    轮次    		会话内一个「用户说 → 模型答」的单元。会话是容器，轮次是单位。07
    单活跃会话全局同时只有一个 session 处于活跃态。换人靠人脸判定切换，不是靠并发开新会话。07
    看门狗
    session watchdog    		判断「这次会话是不是该结束了」的计时器集合：三类倒计时 + 六个暂停源 + 一条保险丝。07
    暂停源能让看门狗停表的六种情况：下屏、导航、TTS、人脸、人体感应、状态门禁。07
    暂停 = 取消，恢复 = 重装暂停时直接取消 timer，恢复时按完整时长重新计时。没有「剩余时间」这个概念——这也是为什么不能把它实现成「暂停一个正在走的倒计时」。07
    无关联点击保险丝屏幕长时间没有与当前会话关联的点击时，强制结束会话。防止一个没人管的会话永远不结束。07
    上下文压缩上下文接近窗口上限时，把旧段落重写成更短的表示，保留结构而不是直接丢弃。≠ 截断：截断会丢掉「办过什么」这类必须留痕的事实。09
    threshold / target
    阈值与目标    		触发压缩的比例（0.75）与压缩后要降到多少（0.60）。两者之间有意识地留出余量，避免刚压完就再次触发。09
    有界批次一次压缩只处理有上限的段落数，避免单次调用吃掉整个预算、或者超时后被整体丢弃。09
    CAS 提交压缩结果写回前校验 revision 与前缀摘要，不一致就放弃本次结果。防止把「基于旧上下文压缩出来的摘要」盖到已经变化的历史上。09
    两类事实
    办过 / 办成了    		「办过」（动作发生过）与「办成了」（结果已确认）分开存，压缩时不许合并。合并的直接后果是模型把「尝试过」说成「已完成」。09
    prompt 版本七个版本共存，由 prompt_version 选择。对话 prompt 可切换，压缩 prompt 在构造时锁死，不许运行期换。10
    按启用工具拼装prompt 里的工具说明由当前启用的工具渲染出来。没启用的工具，模型看不到——所以不会去调一个不存在的工具。10

    D · 设备与场景

    术语定义与边界详见
    数字人
    digital human    		屏幕上会说话的形象，通过长连接收帧、切状态。属于 Integration Adapter。04
    环形麦阵
    ring mic    		环形麦克风阵列，提供唤醒与声源方位。方位只在少数几个状态下被转发。08
    声源方位唤醒时判断人站在哪个方向。只在迎宾驻停、复位移动、巡检移动、迎宾移动这几个状态放行。08
    人体感应
    human proximity    		有人 / 无人的持续事实，不是边沿事件。所以「腿在人不在」不会给看门狗续期。07
    人脸候选
    face candidates    		抓拍到的人脸候选帧。稳定 10 帧 / 1.0 秒才认定为一张可用的人脸，避免路过的人被当成来访者。07
    人脸离开判定去抖 10 帧 + 确认 3.0 秒。侧脸、低头、短暂遮挡都不能立刻判成「人走了」。07
    迎宾点归位判定判断「到没到迎宾点」必须同时看距离与朝向。只看「导航完成」会导致机器人在两点之间来回切换。15
    移动迎宾边走边迎。靠「前方有人」这一事实决定何时停驻收口，而不是让状态机自己去组合人脸与人体信号。08
    巡检
    patrol    		按路线巡逻并上报结果。巡检结果是一条独立链路，不经过对话。08
    回充
    recharge    		回充电桩。两个入口：start_recharge() 只对白名单状态开放，force_recharge() 面向四个驻停态；局部幂等靠复用 operation_id。08
    急停
    EMERGENCY_STOPPED    		唯一能从任意状态进入、且只允许自环或解除到 IDLING_STATIONARY 的状态。08
    启动对账
    reconciliation    		启动后延迟数秒核对真实状态，优先级为 急停 > 充电 > 默认。拿不准时选择不动，而不是猜一个。08

    E · 工程治理

    术语定义与边界详见
    架构守护测试21 条只解析语法树的测试，把「不许这么写」变成会红的 CI。不跑业务代码，所以跑得很快。13
    边界测试只看 import 关系与调用形态，判断有没有越层、有没有第二套实例。≠ 单元测试：它验证的是结构，不是行为。13
    公共合同
    public contract    		一个模块对外承诺的类型集合：Event、Snapshot、Config、方法签名。合同一旦发布，实现可以换，形状不能变。04
    fail-closed拿不准时选择「不动作」，而不是「猜一个继续」。启动对账、状态判定、权限判断都用这条。08
    第二套入口同一个能力存在两条获取路径。明令禁止——一旦有第二条，第一条的约束就形同虚设。03
    Dispatcher
    ActionDispatcher    		把「模型说要干什么」集中翻译成调用的组件。本项目明确禁止，并用一条测试钉死。替代方案是让 Tool 自己就是那个翻译层。03
    工具集整体版本化工具不是逐个上线，而是整套切换。保证「工具集 + prompt」是一个原子版本，回滚时一起回。05
    README / AGENTS 双文档每个模块两份文档：README 写给人看机制，AGENTS 写给 AI 看规则（能改什么、不能改什么）。14
    迁移收口新入口上线后删掉旧入口，不留两套并行。长期并行的结果是谁也不敢删，最后两套都在跑。15
    第一代原型重写前的版本。文中刻意用这个抽象说法，不写它的内部代号。15

    译名对照：为什么这么译

    术语的中文写法本身是一个决定。这里把决定摊开，方便你判断哪些地方我译得不对。

    词正文里怎么写理由
    Adapter保留英文「适配器」在硬件语境里已经被占用了（电源适配器、转接头）。而且代码里的类名就是它，保留英文反而少一层翻译损耗。
    Engine译作「引擎」，与 Adapter 并列时保留英文单独出现时译，因为它需要和「业务状态机」区分；和 Adapter 一起出现时保留英文，因为它们是同一层里的三种东西，用同一套写法更容易看清并列关系。
    Tool译作「工具」「工具调用」在中文里已经是通行说法，不译反而别扭。
    Event译作「事件」通行译法，且「事件驱动」这个词读者已经熟悉。
    fact译作「事实」，不译「事件」这里需要两个层次：Event 是载体，fact 是语义。都译成「事件」就分不出「发了一个事件」和「说的是一件已经发生的事」。
    Reaction译作「反应」，不译「副作用」「副作用」暗示「顺带发生的」，但这里是显式登记、必须执行的动作，译错会让人以为可以不管它。
    Snapshot译作「快照」通行译法，语义准确。
    facade正文保留英文「门面」在中文里太虚，读者容易以为是 UI 层的东西。保留英文并始终写成「公共 facade」，反而清楚。
    Session / Turn译作「会话 / 轮次」Turn 不译「回合」，避免和游戏、对话游戏化场景混。
    revision保留英文译「版本号」会和 prompt 版本、工具集版本混成一团。保留英文，读者一看就知道是那个单调递增的整数。

    如果你熟悉别的架构

    这套东西不是凭空造的，多数概念在别处有对应物。下面给出对应关系，以及差异在哪——差异通常比对应更有信息量。

    这里相近概念差在哪
    AdapterPorts & Adapters 里的 Adapter这里把 Port 也并进了同一个合同：一个模块同时是 Port 和 Adapter，不再分两层接口。
    公共 facadeService Locator只允许存在一个，且禁止构造器注入。Service Locator 被诟病的「依赖不可见」，这里用「import 可以、解析实例不行」这条硬规则限制住。
    Engine进程内 Domain Service只收技术资源，不收业务规则。业务状态机留在 domain 层。
    Toolfunction calling / MCP tool多了两件事：类型化错误输出（不抛异常给模型）、工具集整体版本化。
    SnapshotCQRS 的读模型按模块划分，不按查询划分；每个模块只有一个快照，不按场景裁剪。
    Event Bus进程内 Domain Event明确不保证顺序、不保证幂等、不保证投递。谁依赖，谁自己写清适用范围并测试。
    ReactionSaga 里的后续动作没有补偿回滚，也不保证多个 reaction 的执行顺序；过期即丢弃（靠 revision）。
    转移矩阵状态机的 transition table外置成配置文件，可以被测试直接读、被工具直接校验，而不是藏在代码分支里。
    架构守护测试ArchUnit没有引第三方库，用标准库的 AST 手写。好处是不增加依赖、能查调用形态；坏处是要自己维护。

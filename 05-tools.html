    Tool 体系 05

    18 个能力，模型可以自由选择调用。这一章讲怎么让"加一个能力"只需要写一次声明，而不是在三四个地方各写一遍然后慢慢漂移。

    唯一的执行入口

    execute(tool_input) -> tool_output

    所有 Tool 都用这一个签名，不区分只读和副作用。这是个有意的取舍：分成两类会立刻带来"哪些能并发、哪些要串行、哪些要确认"的矩阵，而这个矩阵在真实场景里永远填不满——比如"查一下附近网点"看起来只读，但它会让机器人开始移动。

    需要"这一轮说完就结束，不要再让模型补一句"的情况，用返回值表达，而不是新增一种 Tool 类型：

    return ToolExecutionResult(output, ToolReplyControl.FIXED_ONLY)

    这个控制标记只活在执行链内部，不进模型 Schema、不进 Event、不进 Session——模型不需要知道自己在被收口。

    代码注册是唯一事实源

    一个 Tool 长什么样，只在一个地方声明：

    ToolRegistration(
    name="query_calendar",
    description="查询节假日、调休与工作日推算",
    input_model=CalendarInput,
    output_model=CalendarOutput,
    implementation=CalendarTool,
)

    从这一条注册项自动推导出：

    • 给模型看的 JSON Schema（从 Pydantic model 推）
    • 能力描述（CapabilitySpec）
    • LangChain 包装后的可调用入口
    • 启动期的启用校验与类型校验

    为什么强调"唯一"：早期 Schema 是手写的，于是出现了"代码里参数叫 target_date、Schema 里叫 date、prompt 里写 targetDate"的三方漂移，模型时对时错，排查花了很久。自动推导之后这类问题从"难查的运行时现象"变成了"编译期就不存在"。

    YAML 只管开关和行为参数

    能放不能放
    enabled凭证、endpoint
    行为参数（超时、阈值、话术模板 ID）连接参数、provider、Real/Mock 选择
    工厂模式下的 kind / factory / config_class实现类路径、Python 对象

    同一字段只能有一个所有者：Tool Config 管"这个能力怎么表现"，Adapter Config 管"连到哪、怎么连"。

    工具集整体版本化

    能力不是一个个上线，而是整套切换：agent.toolset_version 指向一个版本目录，里面是当期全部 Tool 的完整集合。

    这么做看起来笨（改一个工具要复制整套），但它解决了一个真实问题：工具集合变了，prompt 也必须跟着变。如果允许逐个增删，prompt 里"你可以调用 A/B/C"这句话就会和实际注册表脱节，而模型会一本正经地去调一个不存在的工具。整套切换让"工具集 + prompt"成为一个原子版本，回滚时一起回。

    错误也是一种输出

    Adapter 不可用、参数越界、外部超时——这些都不抛异常给模型，而是转成类型化 Output：

    {"ok": false, "reason": "adapter_unavailable", "detail": "..."}

    原因很实际：抛异常会让整轮对话失败，用户听到的是沉默；返回结构化失败，模型还能说一句"这个我现在查不了，您可以……"。在服务场景里，能继续说话比正确更重要。

    测试策略 12

    6.4 万行测试代码，150 多个测试文件。但真正让这个项目没散架的，是其中 21 个不测业务逻辑、只测"代码结构"的测试。

    测试的形状

    层次测什么约束
    unit单个类/函数的合同不碰网络、不碰硬件、不碰真实模型
    integration跨模块链路（graph、设备、检索、存储）用 Mock Adapter 拼装真实 Runtime
    e2e完整会话流固定夹具，可重放
    architecture依赖方向、命名、文档结构、注册表一致性纯静态分析（AST），秒级

    21 个架构守护测试

    它们不做业务断言，只做一件事：把"不许这么写"变成会红的 CI。

    测试挡住什么
    test_domain_has_no_upward_or_adapter_dependenciesdomain 偷偷 import app / adapters
    test_agent_does_not_access_live_adaptersgraph node 直接拿设备
    test_adapters_do_not_depend_on_application_layersAdapter 反向依赖业务层
    test_dispatcher_architecture_is_absent有人重新引入集中分发器
    test_json_freeze_algorithms_exist_only_in_event_bus各模块自制深度冻结
    test_public_events_are_frozen_slotted_dataclasses事件可变、可被订阅者改写
    test_public_adapters_have_contract_structure_and_docs新 Adapter 没 README / AGENTS
    test_yaml_modules_match_code_registration_tablesYAML 与代码注册表对不上
    test_tool_registration_names_are_provider_neutral工具名里混进厂商名

    为什么值得写这些？因为规则文档只能约束愿意读的人。12 个人加 AI 生成代码，靠 review 拦不住"顺手 import 一下"。把规则写成 AST 断言之后，违反规则不再是"评审意见"，而是提交就红。

    而且它顺手解决了 AI 协作的核心问题：AI 不会读完全部文档，但它会读测试报错。

    Mock 合同一致性

    Real 和 Mock 必须导出同一组类型，测试里有一条专门检查公共 Adapter 包不导出 real.py / mock.py 里的类——调用方只能拿到合同，拿不到实现。

    这条看起来吹毛求疵，实际上挡住了一类很隐蔽的退化：某天有人为了图快，在业务代码里 isinstance(adapter, MockChassis) 做分支。一旦允许，Mock 就从"测试替身"变成了"运行期分支条件"。

    默认测试不碰真实世界

    默认用例不依赖真实模型、网络或硬件。这带来两个好处：

    • CI 能在没有设备的环境跑全量；
    • 测试结果稳定，不会因为模型服务抖一下就红一片。

    代价是：测试通过不等于现场能跑。所以还保留了独立的联调脚本和夹具回放，专门覆盖"真实设备行为与 Mock 假设不一致"的情况。

    测试即文档

    每个模块 README 的最后一节固定是"测试"：列出关键测试文件路径 + 一条最小验证命令。想知道一个模块怎么用，比读实现更快的方式是读它的测试。

    pytest -q tests/unit/adapters/test_adapter_runtime.py
